# 项目题：界面取证镜（pattern-lens·暗黑模式取证浏览器扩展·规则可解释·只做取证不做打分）

> **性质**：自拟项目题（**不参赛**，成果发布 GitHub **公开仓库**，署名 `yuluo554`）。交付形态收敛为**唯一形态**：Chrome/Edge **Manifest V3 浏览器扩展**（纯前端、无后端、无模型、无远程代码）。
> **目标产出**：GitHub 公开仓库（本地目录 `10-19-pattern-lens`，`10-19` 为 2026-10-19 日期标签；GitHub 仓库名发布时用纯净名 `pattern-lens`，沿用惯例 `yuluo554/<kebab-name>`）。
> **题目定稿日期**：2026-10-17（查证基准日同此；本文件 v1）
> **题目版本**：v1（首版定稿）
> **定位宣言**：**点一下扩展图标，侧边栏列出当前页所有可疑诱导设计（预勾选、隐形关闭、倒计时施压、假稀缺、确认羞辱……），每条给规则名 + 原文片段 + 元素定位 + 严重度，同时在页面上用编号徽标高亮取证；一键导出证据包。做取证，不做打分——这是与所有"暗黑模式打分器"玩具项目的分水岭：每条结论都必须有可复核的证据节点。**
>
> **独特性拷问（AI 时代必答题）**：LLM 聊天为什么做不到？——它拿不到你**当前这一页渲染后的 DOM**：看不到哪个复选框是页面加载时就被勾上的、哪个关闭按钮被做成了背景色、哪个"仅剩 2 件"背后没有任何库存来源。本工具的独特性落在三处：①**只读渲染后 DOM 的实时取证**（文本节点 + 计算样式 + 元素几何，不截图、不上传）；②**规则即证据模板**（每条规则声明 `evidence_required`，取不到证据节点就拒绝产出结论）；③**可复现测量基建**（合成 fixture 页面 + 植入真值，按规则算 precision/recall，可离线复跑）。它不回答"这个网站有多坏"，只回答"这一页的哪一处、凭什么、算哪条规则"。

## 二、任务要求

> **首期范围限定为五个模块**（M1–M5）；更多规则、规则包热更新、多语言留扩展（§2.6）。
> **形态收敛**：唯一交付形态 = Chrome/Edge Manifest V3 扩展（侧边栏 + content script + service worker），无 CLI、无桌面程序、无后端。
> **权限最小化（硬约束）**：`manifest.json` 只申请 `activeTab` + `scripting` + `sidePanel` + `storage` + `contextMenus`；**不申请** `<all_urls>` / `tabs` / `cookies` / `webRequest` / `history` / `clipboardRead` / `downloads`。权限清单进自动化断言（读 manifest 逐项比对白名单）。
> **只读纪律**：只读**渲染后 DOM**（文本节点、计算样式、元素几何），不改宿主页面内容、不写宿主样式、不发网络请求、不自动点击、不代替用户操作。
> **数值口径一处定义**：严重度分级、precision/recall 门槛、扫描超时、规则匹配优先级、fixture 规模，全部只在 `rules/manifest.json`（M1 落定）定义一次；侧边栏、基准、文档、README 一律引用，**不得手写第二份数值表**。
> **不写会随实现漂移的硬数字**（测试数 / 文件数 / 代码行数）；确需数字时以末态回填。

### 模块 M1：按需注入扫描器

- **输入**：用户点击扩展图标，或页面右键菜单"用界面取证镜检查本页"；当前标签页的 `activeTab` 授权。
- **处理**：
  1. service worker 只做两件事：接收 action 点击 → 打开 sidePanel；接收 sidePanel 的"开始扫描"消息 → `chrome.scripting.executeScript` 注入 `content/scanner.js`；
  2. 注入前先做**站点开关检查**（M5 的黑白名单），命中黑名单直接返回"该站点已停用"，不注入；
  3. scanner 在页面内完成遍历与规则匹配，把 findings 通过 `chrome.runtime.sendMessage` 回传；
  4. **未点击前零注入**：不在 `content_scripts` 里做静态声明注入，`manifest.json` 不声明任何 `content_scripts` 条目。
- **输出**：`ScanResult{url, scanned_at, node_count, findings[], elapsed_ms}`。
- **确定性纪律**：同一页面同一规则包 → findings 的规则集合与排序稳定（按 `severity` 降序，同级按 DOM 文档序）；扫描超时（阈值见 `rules/manifest.json`）必须返回**部分结果 + `truncated: true`**，不得静默返回空结果；注入失败必须显式报错。
- **验收**：未点击前 DevTools 的 Sources 面板**无 scanner 脚本**（零注入）；点击到侧边栏出结果 **< 500ms**（5k 节点页面，阈值来源 `rules/manifest.json`）；manifest 权限断言通过。

### 模块 M2：规则引擎 + 规则包

- **输入**：扫描器采集的 DOM 特征集合（文本节点、属性、计算样式、几何）+ 内置规则包 `rules/dp-*.json`。
- **处理**：
  1. 规则包随扩展打包，**版本化**（`rules/manifest.json` 记版本号与内容哈希），无远程代码、无热更新拉取；
  2. 首批 **12 条规则**：预勾选、隐形关闭、倒计时施压、假稀缺（"仅剩 N 件"但无库存来源）、确认羞辱、锚定折扣、默认加购、退出挽留多层、订阅陷阱（"仅电话取消"）、隐藏费用后置、强迫注册、暗色关闭按钮；
  3. 每条规则必须含 `rule_id` / `severity` / `evidence_required` / `explanation` / `locator_strategy`；
  4. 引擎对每条规则产出 `Finding{rule_id, severity, snippet, locator, evidence, explanation}`，**`evidence_required` 未满足 → 不产出 finding**（不是降级为低置信，而是丢弃并计入 `rejected[]`）。
- **输出**：`findings[]` + `rejected[]`（每条带未满足的证据项，供调试与基准统计）。
- **确定性纪律**：规则匹配优先级（同一节点命中多条规则时的归属）在 `rules/manifest.json` 定义一次；规则解释文本从规则包读取，**不得在 UI 里手写第二份解释**；snippet 必须是宿主文本节点的**原样子串**（截断时记 `snippet_truncated: true`）。
- **验收**：`data/fixtures/` 共 40 个合成页面（每页植入真值标注），单规则 **precision ≥ 0.90、recall ≥ 0.80**（门槛定义在 `rules/manifest.json`）；无证据节点的规则**零产出**。

### 模块 M3：页内取证高亮层

- **输入**：M2 的 findings（含 locator 与编号）。
- **处理**：
  1. 用 **Shadow DOM** 建覆盖层，宿主页面只被插入一个容器节点；样式全部在 shadow root 内，**不写宿主样式**；
  2. 每个 finding 在对应元素旁显示编号徽标（与侧边栏列表编号一致）；
  3. 侧边栏点击条目 → 页面滚动定位并闪烁对应徽标；页面点击徽标 → 侧边栏高亮对应条目（双向联动）；
  4. 提供"清除取证层"，移除插入的容器与全部徽标。
- **输出**：覆盖层节点树 + 编号映射 `{finding_id: badge_id}`。
- **确定性纪律**：清除后页面 DOM 必须与扫描前**完全一致**（属性 / 节点数 diff = 0，用扫描前后快照比对断言）；不修改任何宿主元素属性；不插入 `<style>` 到宿主 `document.head`；同一 finding 重复高亮不产生重复徽标。
- **验收**：DOM 快照 diff = 0 测试通过；徽标编号与侧边栏编号一一对应；宿主 `document.styleSheets` 数量不变。

### 模块 M4：侧边栏取证台

- **输入**：`ScanResult` + 当前站点设置。
- **处理**：
  1. 分组展示：**紧迫 / 误导 / 障碍 / 价格**（分组归属由规则包的 `category` 字段决定，不在 UI 写死）；
  2. 每条展示：编号、规则名、原文片段、规则解释、严重度、元素定位（可复制）；
  3. 站点级折叠：同一站点的多次扫描结果按时间倒序折叠，默认展开最新一次；
  4. 结果写入 `chrome.storage.session`，sidePanel 冷启动或 service worker 被回收后重开仍能恢复上次结果。
- **输出**：侧边栏 DOM + `storage.session` 中的 `LastScan` 记录。
- **确定性纪律**：分组顺序与条目排序稳定；解释文本只来自规则包；空结果必须显示"本页未发现符合规则的证据"并附扫描时间与节点数，**不得显示"安全/无风险"这类定性结论**。
- **验收**：冷启动恢复测试（关闭 sidePanel → 重新打开 → 结果一致）；SW 被 kill 后重开仍可恢复；分组与排序断言通过。

### 模块 M5：证据导出 + 站点设置

- **输入**：`ScanResult` + 站点设置。
- **处理**：
  1. 导出 **Markdown / JSON** 两种格式，含 URL、扫描时间戳、规则名与解释、原文片段、元素定位、严重度；**不含截图**；
  2. 导出走 **Blob + `<a download>`**，全本地，不经过任何服务器；
  3. 站点黑白名单（永不在某站注入 / 仅在某站启用）与规则开关（逐条 `rule_id` 启用/禁用），存 `chrome.storage.local`；
  4. 导出文件名含站点主机名与时间戳（不采集额外个人数据）。
- **输出**：下载的 `.md` / `.json` 文件 + 设置存储项。
- **确定性纪律**：导出字段顺序固定（同一 `ScanResult` 导出两次字节一致）；禁用某规则后该规则不参与扫描且不出现在导出中；站点黑名单命中时**不注入**（M1 联动）。
- **验收**：导出文件字段完整性断言；导出两次字节一致；DevTools Network 面板观察**整轮扫描 + 导出 0 次网络请求**。

## 六、边界与非目标

- **不做打分 / 不做评级**：不产出"暗黑模式分数""欺诈指数"，只产出逐条证据；这是与"打分器"玩具项目的分水岭，也是避免误导性宣称的底线。
- **不做自动点击 / 不代用户取消订阅 / 不自动填表**：不代替用户操作，不绕过任何流程。
- **不做页面内容存档**：不截图、不存整页 HTML、不保存用户输入。
- **不做 ML 识别**：所有结论必须由可读的规则与证据节点支撑，规则可逐条开关、可审计。
- **不申请宽泛权限**：权限白名单见 §二，`<all_urls>` / `tabs` / `cookies` / `webRequest` / `history` / `clipboardRead` / `downloads` 一律不申请。
- **隐私红线**：不采集、不上传、零遥测；不读取登录态；扫描结果只存本机 `storage.session` / `storage.local`。
- **文案红线**：全站统一"可疑模式（待核对）"，不写"欺诈""违法""恶意网站"；每条结论必须附规则解释与原文片段。
- **品牌隔离**：本题文档不提名、不复用本系列其他项目的代码与业务描述。
- **首期范围**：12 条规则，不做全量暗黑模式分类学；规则包热更新、多语言、PDF 导出留扩展。
- **免责**：工具结论是"可疑模式（待核对）"，不构成法律意见或事实认定；导出证据包仅供人工复核。
