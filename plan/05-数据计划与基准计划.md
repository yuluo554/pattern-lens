## 二、真值纪律（真值只存输入与期望）

1. **真值先于规则**：每页的 `truth.json` 先定标，再写规则；禁止"规则能测什么就标什么"。
2. **只存输入与期望**：`truth.json` 每项 = `{ rule_id, selector_path, snippet_expected, note? }`。
   - **出现 `observed_*` / `matched` / `detected` 一类字段即红**（冻结"观测"会让基准退化成
     "比对两份预先算好的答案"——引擎全坏也全绿）；配守门 `tests/truth-shape.test.mjs`。
   - `snippet_expected` 必须是 `page.html` 的**原样子串**（生成器断言 + 基准对账双查）。
3. **期望值可由输入独立复算**：`selector_path` 指向的节点文本与 `snippet_expected` 的包含关系，
   由基准侧用**独立读取路径**（直接解析 `page.html`）复算，不依赖被测引擎（防"期望值与实现同源"）。
4. **负样本必须存在**：40 页里必须有"看起来像但按规则不成立"的页（如可一键取消的订阅、有库存来源的"仅剩 2 件"），
   用于压 precision。**只测正例的套件里，适用域写错永远不会红**。
5. **偏科检查**：`COVERAGE.md` 逐规则记正/负样本计数；样本不足的规则显式标"覆盖弱"，
   **不得**用其他规则的样本充数，也不得为了让基准好看而降低该规则的证据门槛。

## 三、生成器纪律（确定性）

- 自研 `src/lib/rng.js`（splitmix64）：**禁 stdlib `random`/`Math.random`、禁 set 迭代序、禁系统时钟**
  （落盘产物**无时间戳**）。
- **两层都断言**（只断言冻结产物的守门，在生成器被改坏时照常绿）：
  ① `tests/fixtures-frozen.test.mjs` 断言**盘上冻结产物**形态正确（40 页齐、真值字段齐、无 `observed_*`）；
  ② `npm run fixtures:check` = 重跑生成器到临时目录 → 与冻结产物**逐字节比对**。
  变异项：把生成器改坏（如把某页的真值写空）→ 两层里至少一层必红。
- **手工修改 fixture 必须同步改 `truth.json`**，否则 `fixtures:check` 失败。
- 台账/清单类文件（`COVERAGE.md`）是**生成物**，不手编；每格必须能由 `truth.json` 复算，
  且**跨环境复算结果相同**（禁止登记"目录里实际有几个文件"这类环境依赖事实）。

## 四、基准计划

| # | 基准段 | 覆盖 | 阈值来源 | 缺失时的行为 |
| --- | --- | --- | --- | --- |
| B1 | 逐规则 precision/recall（40 页） | FR-04/05、M2 DoD | `rules/manifest.json` `thresholds` | 缺 fixture → **FAIL** |
| B2 | 证据门禁零产出 | FR-05 | 无阈值（集合为空） | 缺用例 → FAIL |
| B3 | 排序与编号稳定（双跑） | FR-06 | 无 | 缺用例 → FAIL |
| B4 | snippet 原样子串（含截断） | FR-07 | `snippet_max_len` | 缺用例 → FAIL |
| B5 | locator 回解唯一 | FR-08 | 无 | 缺用例 → FAIL |
| B6 | 超时部分结果 | FR-09 | `scan_timeout_ms` | 缺用例 → FAIL |
| B7 | 5k 节点耗时 | NFR-06 | `first_result_budget_ms` | 缺压力页 → FAIL |
| B8 | 导出字段完整 + 双跑字节一致 | FR-16/17 | 无 | 缺用例 → FAIL |
| B9 | 零网络 / 零外链 / 零远程代码 | NFR-03/04 | 计数 = 0 | 缺扫描面 → FAIL |
| B10 | DOM diff = 0（清除后） | FR-12 | 无（三项皆为 0） | 缺用例 → FAIL |

### 4.1 双边门（**只守"没有误报"的门，在引擎整体失效时照样全绿**）

B1 必须**双边**：

| 边 | 判据 | 反例（必须能红） |
| --- | --- | --- |
| 误报边 | 每条规则的 `false_positive = 0`（负样本上不得命中） | 收紧证据门槛过头 → recall 掉到门槛下 |
| 检出边 | 每条规则的 `recall ≥ thresholds.recall_min` | 放宽匹配 → precision 掉到门槛下 |

配套四条（缺一则 B1 是假门）：
① **逐样本点名**：任何差异必须落到具体 `page-NN / rule_id`（防汇总率掩盖"某类全零"）；
② **逐规则覆盖下限**：`COVERAGE.md` 的正样本数 < `rules/manifest.json` `thresholds.min_cases_per_rule` 的规则 → FAIL；
③ **错误归属逐样本核对**：不能只查"是否判 invalid"，要核对该样本**命中的规则 id 是否等于真值声明的 id**；
④ **探活（可证伪）**：往引擎注入一个已知缺陷（如把某规则的证据门禁短路）→ B1 必须报未达标。
探活变红后立即还原，并断言字节已还原（防"变异没真发生"的静默 no-op）。

### 4.2 植入器自证（若基准含"植入错误样本"环节）

植入器每次改动前**断言锚点存在**、改动后**断言字节已变**，任一不成立即抛错
（`str.replace` 锚点失配会静默返回原文，于是"样本里有错"是假的而基准照常跑）。

### 4.3 覆盖面声明（不许把"没做"说成"通过"）

- 基准输出必须打印**总数/采样数双登记**（如"12 规则 × 40 页 = 480 个 (规则,页) 组合，实跑 480"），
  并显式写"这是合成基准，非穷举真实站点"。
- 某规则在 fixture 上**无负样本**时：该规则的 `precision` 记 `not_assessed`（**不填 1.0**），
  在输出里显式列出——"没有反例"不等于"精度 100%"。

**纪律**：
- 任何文档、UI、测试里**不得**出现第二份阈值数字；需要时写"阈值见 `rules/manifest.json`"；
- 门槛是**数据不是代码**：调整门槛只改 manifest，不改引擎；
- 配门禁：把 manifest 里的数值收编为禁用 token（词边界），扫描 `src/**` 与 `rules/dp-*.json`——
  数值只能来自 manifest。豁免口径（如 `< 100` 的小整数 = 日历/精度常数）写死在门禁里。
- 调整门槛须在 `plan/00` §2 决策记录留行，并同步三处（`plan/01` 题面口径 / manifest / README）。
