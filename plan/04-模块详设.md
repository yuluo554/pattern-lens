## M1 · 数据先行（fixture 与真值）

- **输入**：无外部数据（D17：一律合成）。假站点名白名单见 `data/README.md` §3.1。
- **处理**：
  1. `tools/gen-fixtures.mjs` 用 `src/lib/rng.js`（splitmix64，固定 seed）生成 **40 页** fixture：
     每页一个目录 `data/fixtures/page-01/`，内含 `page.html`（含 inline style 与 `<style>` 块）+ `style-map.json`
     （生成器同步产出的**声明样式子集**，见 `plan/03` §六）+ `truth.json`（植入真值）；
  2. 真值**先于规则**：先写 `truth.json` 再写规则（防"规则能测什么就标什么"）；
  3. 每页至少含 1 个**正样本**与（部分页）**负样本**（看起来像但按规则不成立，用于压 precision）；
  4. 产出 `data/fixtures/COVERAGE.md`：12 规则 × 正/负样本计数矩阵；样本不足的规则显式标"覆盖弱"。
- **输出**：`data/fixtures/page-NN/{page.html,style-map.json,truth.json}` + `data/fixtures/COVERAGE.md`。
- **失败路径**：白名单外的站点名/域名 → 生成器**报错退出**（不静默替换）；真值里出现不在规则包内的 `rule_id` → 报错。
- **判定语义**（真值纪律，`plan/05` §二详述）：真值只存**输入与期望**（`selector_path` + `snippet_expected` + `rule_id`），
  **不得出现 `observed_*` 一类字段**（冻结"观测"会让基准退化成比对两份预先算好的答案）。
- **逐形态验收**：① 40 页全部落库且 `truth.json` 可被 `JSON.parse`；② `npm run fixtures:check` 再生成**位级一致**；
  ③ 覆盖矩阵每规则正/负样本计数与真值文件实测计数一致（生成器断言）；④ 每页 `snippet_expected` 是 `page.html` 的原样子串。

**落地记录（M1，2026-10-19）**：`tools/gen-fixtures.mjs` 真生成器已落地（`--check` 位级一致；白名单/真值形态/覆盖下限**生成期断言**）。
真值文档形态 = `{page, site, url, positives[], negatives[]}`（两类条目形态统一 = `{rule_id, selector_path, snippet_expected, note?}`；见 `plan/00` D26）；真值落在页目录内（D25）；压力页规模读 `thresholds.stress_node_count`（D27）。
守门两层：`tests/truth-shape.test.mjs`（真值形态 + `page.html` 独立回解 + 白名单 + 覆盖下限，含 7 组变异）、
`tests/fixtures-frozen.test.mjs`（冻结产物形态 + `COVERAGE.md` 复算 + `fixtures:check`，含 4 组变异）。
**已知建模缺口（M2 处理）**：容器元素的 `label` 取 `textContent`，会让"允许 element 的文本级规则"在祖先容器（含 `body`/`html`）重复命中；
M1 真值只对**控件/文本节点**对账，口径写在 `data/fixtures/README.md`。

## M2 · 规则引擎与按需注入

- **输入**：`PageModel`（采集器产出）+ 规则包（`rules/manifest.json` + `rules/dp-*.json`）。
- **处理**：
  1. SW 收到 `start-scan` → 读站点开关（`storage.local`）→ 命中黑名单回 `blocked-site`**不注入** → 否则
     `chrome.scripting.executeScript({ target: { tabId }, files: ["scanner.js"] })`；
  2. 采集器遍历渲染后 DOM，产出节点序列 `{ seq, kind, text, attrs, style, box, locator }`——`seq` 是**文档序下标**（同一棵树内稳定）；
  3. 引擎按 `rules/manifest.json` 的 `match_priority` 决定同一节点多规则命中时的归属；
  4. 每条规则产出候选后过**证据门禁**：`evidence_required` 逐项在节点上取值；取不到的候选**丢弃**并进 `rejected[]`；
  5. 排序（`ordering.js`：severity 降序 → DOM 文档序）→ 编号 → `ScanResult` 回传；SW 落 `storage.session.LastScan`。
- **输出**：`ScanResult{url, scanned_at, node_count, elapsed_ms, truncated, ruleset_version, ruleset_hash, disabled_rule_ids[], findings[], rejected[]}`。
- **失败路径**：注入失败 → 显式报错（侧边栏显示"注入失败：<reason>"，不显示"未发现"）；
  规则包缺必需字段或枚举越界 → **拒绝加载**（`rules.js` 抛错，列出缺项）；扫描超时 → 部分结果 + `truncated: true`。
- **判定语义**（本项目的核心口径）：
  - **证据门禁不是降级**：`evidence_required` 未满足 → **丢弃**（不是低置信、不是待确认），并记 `rejected[]` 供调试与基准统计；
    `rejected` 条目带 `reason`：`missing_evidence`（取不到证据）/ `suppressed`（被中和项抑制）/
    `duplicate_locator`（同一 `(rule_id, locator)` 已出过一条，见 K26）——**"没命中"与"被中和"与"被去重"是三种事实**；
  - **空串算"取到了"**：`text`/`nearby-text` 返回 `""` 是合法证据（"这个区域确实没有别的文本"），
    只有 `undefined`（取不到）才触发门禁——两态必须分清，否则假稀缺类规则永远不产出；
  - **解释文本单一来源**：`finding.explanation` 必须**逐字等于**规则包的 `explanation`（`tests/explanation-single-source` 由 `rules-schema` 段覆盖）；
  - **`limits` 必填**：每条规则必须显式声明"本工具不判断什么"（校验器缺它即拒绝加载）——把"待核对"写进数据，而不是只写进文档；
  - **snippet 原样**：`snippet` 必须是宿主文本节点的原样子串（不 trim 中间、不做归一化）；
    超 `snippet_max_len` 时**只从尾部截断**并记 `snippet_truncated: true`；
  - **样式条件两档**：`detect.style` = 全部成立（AND）；`detect.style_any` = 任一组成立（OR）——
    "极小 **或** 与背景同色"必须用 `style_any`，写成单个 `style` 会变成"必须同时满足"（实测踩过：
    两条关闭类规则都因此永不命中，而测试与规则数据同错时不会红）；
  - **`near_text_any` 的文本池** = 自身文本/标签 + 周边文本（控件常常只有标签，没有子文本）；
  - **`nearby_absent_any`** = 这些正则**在周边文本里都不出现**才算命中（"没有可核对来源"这一事实本身就是证据）；
  - **不产出定性结论**：finding 只描述"观察到什么 + 命中哪条规则"，不写"该站点在欺骗用户"。
- **逐形态验收**：① 单规则 precision ≥ `thresholds.precision_min`、recall ≥ `thresholds.recall_min`（阈值读 manifest）；
  ② 无证据节点规则**零产出**（变异验证：去掉证据节点 → findings 归零、`rejected` 非空）；
  ③ 权限白名单断言通过；④ manifest 无 `content_scripts`；⑤ 5k 节点页面耗时 < `thresholds.first_result_budget_ms`；
  ⑥ 超时分支返回部分结果且 `truncated: true`；⑦ 排序双跑一致。

**落地记录（M2，2026-10-19）**：引擎/采集器/注入链路 + 基准全部落地，逐条对上本节 DoD：

- **页面模型解析器（Node 侧）**：`tools/fixture-page-model.mjs` —— **独立于生成器**（只读盘 + 自写 HTML 解析 +
  `src/lib/page-model.js` 的工具复算），从 `page.html` + `style-map.json` 产出与采集器同语义的 `PageModel`（K24）。
  缺 `style-map` 声明即**报错**（不静默取默认值）；压力页（生成器不产 style-map）落回声明默认样式（D28）。
- **⚠ 已知建模缺口的处置（决策 D29）**：`label` 的回退**只对控件**用自身文本；普通元素只取显式标签属性
  （`aria-label`/`title`/`placeholder`/`alt`），不取 `textContent`。口径**单点**落在 `src/lib/page-model.js` 的
  `labelFrom()`（采集器、基准侧、生成器三处同调）。反事实对照（`tests/rules-bench.test.mjs`）：把缺口形态恢复后
  **整页**重扫引擎：实测 133 条 finding / **85 条误报**；四条文本级规则（`dp-countdown-pressure`/`dp-anchored-discount`/`dp-exit-retention`/`dp-hidden-fee`）precision 掉到 **0.1379~0.1667**——证明这条口径是**载荷**的（常驻 2 项断言）。
- **同一 locator 去重（K26）**：引擎按 `(rule_id, locator)` 去重（先到先得 = 文档序在前者胜），被丢的候选记
  `rejected[].reason = "duplicate_locator"`（**不静默**）。理由：文本节点与其宿主**控件**共用同一 `tag:nth(i)` 定位串，
  两条都产出会让同一条证据在清单里出现两次。
- **性能（NFR-06）**：周边文本改"按需翻倍前缀"归一（`limitNearText`，语义与通篇归一等价，工作量 O(limit×常数)）——
  原先对每个子节点归一整个父容器文本（压力页 2500 行 × ~25k 字符），实测冷启动 **1313ms**，超 500ms 预算；
  改后 5007 节点解析 + 判定 **冷 106.5ms / 热 114.2ms**。
- **基准 B1–B7**（`tools/bench-rules.mjs` + `tests/rules-bench.test.mjs`）：逐规则 precision/recall **双边门**
  （precision ≥ 0.9 / recall ≥ 0.8 / 误报边 = 0）、逐样本点名、覆盖下限逐规则点名；B2 证据门禁（**按类断供证据**
  + 反向对照 + 按引用还原自证）；B3 双跑字节一致；B4 snippet 原样；B5 locator 回解唯一 + 去重；
  B6 超时部分结果；B7 压力页耗时。**探活 3 组**（引擎侧中和项短路 → precision 边红；数据侧删 `nearby_absent_any`
  → 误报边红；数据侧加不可满足 `text_all` → recall 边红），每组变红后还原并**断言字节已还原**。
  实测：**48 正 / 24 负 / 48 finding / 0 误报 / 8 rejected（全为 `suppressed`）**，12/12 规则达标。
- **阈值 token 门禁**：`tests/threshold-token.test.mjs`（K1 的 M2 补门）——manifest 阈值作为禁用 token 扫
  `src/**` 与 `rules/dp-*.json`（剥注释后扫）；两条**已声明豁免**：① `src/lib/rules-pack.js` 是 manifest 的生成物镜像
  （另配断言证明它逐键等于 manifest）；② **整数且 < 100** 的 token（本项目里是 slice 宽度/枚举行数类常数）。
  阳性对照 + 阴性对照 + 豁免清单打印齐备。
- **按需注入链路**：`tests/injection-chain.test.mjs` —— 用假 chrome 运行时把 SW 的 `start-scan` → 站点开关 →
  `executeScript({files:["scanner.js"]})` → `scan-result` → `storage.session.LastScan` 全链路跑成**离线**断言，
  含**否定性事实**（黑名单命中时 `executeScript` 一次都没被调用）与注入失败显式报错。
  为此 `src/background/service-worker.js` 加了 `HAS_RUNTIME` 守卫（无扩展运行时时不挂监听，模块可被单测 import）。
  **口径**：这是**本地等价校验**；真实浏览器冒烟仍未做（`plan/06` §五），不据此打"浏览器已验"。

**M2 实测缺口（如实登记，不当成已解决）**：① 语料侧"命中但证据取不到"的候选实测 **0 个**（B2 探针会数出来），
故 B2 用"按类断供证据"的可证伪方式验证门禁，语料本身不覆盖这条路径；② snippet **截断分支**在本语料上实测
**未走到**（B4 的 `truncated` 计数 = 0）——该分支由 `tests/snippet-verbatim.test.mjs` 的单测覆盖，基准侧不冒充已验。

## M3 · 页内取证高亮层

- **输入**：`findings[]`（含 `locator` 与编号）。
- **处理**：
  1. 建 Shadow DOM 覆盖层容器（宿主页面只多**一个**容器节点），样式全在 shadow root 内；
  2. 每个 finding 在其元素旁渲染编号徽标（编号与侧边栏一致，映射 `{finding_id: badge_id}`）；
  3. 侧边栏点条目 → 滚动定位 + 闪烁对应徽标；点页面徽标 → 侧边栏高亮条目（双向联动）；
  4. "清除取证层" → 移除容器与全部徽标。
- **输出**：覆盖层节点树 + 编号映射。
- **失败路径**：`locator` 回解不到节点（页面已变化）→ 该条目标"元素已失效（页面可能已变化）"，**不静默跳过**；
  重复高亮同一 finding → 不产生重复徽标（幂等）。
- **判定语义**：不修改任何宿主元素属性、不插入 `<style>` 到宿主 `document.head`、不写宿主内联样式。
- **逐形态验收**：① 清除后 DOM 快照 diff = 0（属性集 / 节点数 / `document.styleSheets.length` 三项）；
  ② 徽标编号与侧边栏编号一一对应；③ 重复高亮幂等；④ locator 失效分支显式可见。

## M4 · 侧边栏取证台

- **输入**：`ScanResult` + 站点设置。
- **处理**：
  1. 四组分组渲染（紧迫/误导/障碍/价格，分组顺序由 `rules/manifest.json` 的 `categories` 数组决定；
     条目归属由规则包 `category` 决定，**UI 不写死**）；
  2. 每条展示：编号、规则名、原文片段、规则解释、严重度、元素定位（可复制）；
  3. 站点级折叠：同站点多次扫描按时间倒序折叠，默认展开最新一次；
  4. 结果读 `chrome.storage.session.LastScan`；冷启动或 SW 被回收后重开仍能恢复。
- **输出**：侧边栏 DOM + `storage.session` 的 `LastScan` 记录。
- **失败路径**：`LastScan` 为空 → 显示"尚未扫描本页"（不显示空结果文案）；`LastScan.url` 与当前标签页不同 →
  显示上次结果并标"这是 <host> 上次的扫描结果"，不冒充当前页。
- **判定语义**：空结果必须显示"**本页未发现符合规则的证据**"+ 扫描时间与节点数；
  **禁止**"安全 / 无风险 / 未发现问题"这类定性结论（`tests/copy-guard.test.mjs` 的禁用词表）。
- **逐形态验收**：① 冷启动恢复一致；② SW 被回收后恢复一致；③ 分组与排序断言通过；④ 空结果文案走 copy 单点。

## M5 · 证据导出与站点设置

- **输入**：`ScanResult` + 站点设置。
- **处理**：
  1. 导出 Markdown / JSON（字段：URL、扫描时间戳、规则包版本与哈希、规则名与解释、原文片段、元素定位、严重度、编号）；
  2. 导出走 `Blob` + `<a download>`，全本地，不经服务器；文件名含 host 与时间戳；
  3. 站点黑白名单（永不注入 / 仅在某站启用）与规则逐条开关，存 `storage.local`；
  4. 导出**不含截图**、不含整页 HTML、不含用户输入。
- **输出**：`.md` / `.json` 文件 + 设置存储项。
- **失败路径**：`ScanResult` 缺字段 → 导出函数抛错（**不补默认值**，防"看起来完整的证据包"）；
  禁用某规则后 → 该规则不参与扫描、不出现在导出（含 `rejected[]` 与 `ruleset` 列表）。
- **判定语义**：字段顺序固定（同一 `ScanResult` 导出两次**字节一致**）；
  禁用规则集合写进导出的 `ruleset.disabled_rule_ids`（可复核"这份证据包用了哪些规则"）。
- **逐形态验收**：① 字段完整性断言；② 双跑逐字节一致；③ 整轮扫描 + 导出 0 次网络请求；
  ④ `docs/商店素材清单.md` 与 `assets/store/` 实物逐项对账；⑤ `docs/隐私声明.md` 与权限白名单一致。

## 附：模块间的"不可越界"清单（AST 守门的判据来源）

| 约束 | 为什么 | 守门 |
| --- | --- | --- |
| `src/lib/**` 之间零 import | 自写拼接要求扁平依赖序（D14） | AST 守门（`tests/source-hygiene.test.mjs`） |
| 判定核心不读 storage / DOM / chrome API | 纯函数才能离线基准 | AST 守门：`src/lib/engine.js` 等文件不得出现 `chrome`/`document`/`window` |
| 阈值数字不出现在 `src/` 与 `rules/dp-*.json` | 数值口径单点（D11） | 门禁扫描 `rules/manifest.json` 里的数值 token |
| 文案不出现在 UI 层硬编码 | 文案单点 | 扫描 `src/sidepanel/**`，关键词必须在 `src/lib/copy.js` |
| 采集层不写宿主 | 只读纪律（NFR-02） | 扫描 `src/content/**`：禁 `document.head.appendChild`/`style` 赋值等形态 |
