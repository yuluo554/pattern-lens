## 二、逐棒 DoD（每棒收尾时必须逐项有证据）

### M1 DoD

- [ ] `data/fixtures/` 有 40 页，每页 `page.html` + `style-map.json` + 真值
- [ ] 真值只含 `{rule_id, selector_path, snippet_expected, note?}`，**无 `observed_*` 一类字段**
- [ ] `snippet_expected` 在 `page.html` 里**逐字出现**（生成期断言，40/40）
- [ ] 站点名/域名全部落在 `data/README.md` §3.1 白名单内（生成器断言）
- [ ] 每规则 ≥ `thresholds.min_cases_per_rule` 个正样本；负样本覆盖"看起来像但不成立"的页
- [ ] `COVERAGE.md` 由真值汇总生成，计数与真值文件实测一致
- [ ] `npm run fixtures:check` 通过（重生成与冻结产物逐字节一致）
- [ ] 冻结产物形态守门 + 再生成守门**两层都在**（变异：改坏生成器 → 至少一层红）

### M2 DoD

- [ ] `rules/manifest.json` 含版本、阈值、枚举、匹配优先级、fixture 规模（**唯一数值真相源**）
- [ ] 12 条规则全部含 `rule_id`/`name`/`category`/`severity`/`detect`/`evidence_required`/`locator_strategy`/`explanation`
- [ ] 逐规则 precision ≥ `thresholds.precision_min`、recall ≥ `thresholds.recall_min`（双边门 + 逐样本点名）
- [ ] 无证据节点的规则**零产出**（变异验证：去掉证据节点 → 归零且 `rejected` 非空）
- [ ] 同一页面同一规则包 findings 排序稳定（双跑逐字节一致）
- [ ] 5k 节点页面：点击到出结果 < `thresholds.first_result_budget_ms`
- [ ] 超时 → 部分结果 + `truncated: true`（不得静默返回空）
- [ ] manifest 无 `content_scripts`；权限白名单断言通过（`host_permissions` 为空）
- [ ] 阈值 token 门禁：`src/**` 与 `rules/dp-*.json` 内无第二份阈值数字

### M3 DoD

- [ ] 覆盖层为 Shadow DOM，宿主页面只多一个容器节点
- [ ] 清除后 DOM 快照 diff = 0（属性集 / 节点数 / `document.styleSheets.length` 三项）
- [ ] 徽标编号与侧边栏编号一一对应；重复高亮幂等
- [ ] 双向联动可用（浏览器冒烟：真实点击；缺浏览器时显式 SKIP 并记入已知未验证项）
- [ ] locator 失效分支显式提示，不静默跳过

### M4 DoD

- [ ] 四组分组顺序与条目归属来自规则包（改规则包 → UI 跟着变，UI 无硬编码）
- [ ] 冷启动恢复一致；SW 被回收后重开仍可恢复
- [ ] 空结果文案 = "本页未发现符合规则的证据" + 扫描时间 + 节点数（禁用词扫描通过）
- [ ] 结果落 `chrome.storage.session`，`LastScan` 结构含 `url`/`scanned_at`/`scan_result`

### M5 DoD

- [ ] Markdown 与 JSON 导出字段完整（含规则包版本与哈希、禁用规则列表）
- [ ] 同一 `ScanResult` 导出两次**字节一致**
- [ ] 整轮扫描 + 导出 **0 次网络请求**（源码断言 + 浏览器冒烟 resource 计数；缺浏览器时如实标注）
- [ ] 站点黑名单命中 → 不注入（且 UI 明示"该站点已停用"）
- [ ] 规则开关生效：禁用规则不参与扫描、不出现在导出
- [ ] `docs/商店素材清单.md` 与 `assets/store/` 实物逐项对账；`docs/隐私声明.md` 与权限白名单一致
- [ ] `README.md` 定稿（安装、使用、规则说明、隐私承诺、局限披露）

### M6 DoD（三件套）

- [ ] git tag（annotated）`v0.1.0`，指向发布提交，已推远端
- [ ] GitHub Release，附件 = 确定性 zip（本地留副本 + sha256 登记在 **Release 正文**，**不写进包内**）
- [ ] `plan/RELEASE-M6.md`（tag 前入库，两栏：tag 前事实 / tag 后追加）+ 阶段 7 覆盖对账表（三态逐条）
- [ ] `node tools/check-release.mjs --online` 无 FAIL
- [ ] 发布后：干净 clone 复核 + 附件真下载 `sha256` 对齐 + tag 树重建产物 `cmp` 逐字节一致

## 六、状态回写纪律

1. 每棒收尾顺序固定：**DoD 逐项验证 → 回写 `plan/00` §5 + 本文件 §一 + `README.md` 状态行 → 写 `plan/HANDOFF-M<next>.md` → commit →（有远端）push 等 CI 绿**。
2. 三处状态副本必须**同一次提交**改完；漏一处 = 布局门红（这是刻意的）。
3. 未达成的 DoD 项写"偏差说明"（原因 + 替代验证方式），**不许**把 ⬜ 改成 ✅。
4. 历史文档保留原措辞，补记是**追加事实**不是回填美化。
